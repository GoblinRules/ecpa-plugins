Existing login imports a credential copy from GitHub CLI into the Windows vault. It keeps your active gh account unchanged. If the original credential is revoked, sign in again. Codex and Claude keep managing their own agent logins.

For browser sign-in only: GitHub CLI briefly stores the login in a temporary profile; the helper imports it into Windows Credential Manager and removes the profile on normal exit.

Wrangler login and remote MCP OAuth

Cloudflare currently uses API tokens here. Isolated Wrangler browser logins are not supported yet. Remote MCP OAuth is a separate session: add the remote server in your agent and use that agent's sign-in flow. These sessions cannot be shared just by assigning a project here.

Use a token scoped to the account and tasks you need. The saved token is never returned to this page. GitHub supports personal access tokens; Cloudflare uses API tokens. Portainer uses an access token, saved in the same Windows vault.

Optional: accounts for a project

Add your first account using + New connection before assigning a project.

Choose accounts for a folder, then launch a tool using the generated project command. Existing agent sessions do not change. Subfolders inherit the nearest assignment.

Choose “None” for both services to remove an assignment. This does not change your agent configuration or global logins.

Tool paths and arguments

Wrangler: use node.exe and the full path to wrangler/bin/wrangler.js as the first argument. MCP: choose your server executable and arguments. Batch files (.cmd/.bat) are not supported. Git SSH identities and browser logins remain separate.

MCP snippets can be added through MCP Manager's advanced editor (use the individual server definition), or merged into the agent config. No tokens are included. The helper forwards stdin/stdout for stdio MCP servers. For arbitrary agent sessions, launch the agent executable through the same helper; child tools inherit the selected credentials.
