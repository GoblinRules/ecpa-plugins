Unlock management

Kept in memory for this page only. Machine keys and logins are handled by OpenSSH under the ECPA host's Windows identity.

Add machine

SSH must already be enabled on the target. A Tailscale address supplies reachability; it does not install SSH or register a T3 runner.

Each profile selects exactly one identity. Password login, agent forwarding, inherited SSH config, proxy commands and connection sharing are disabled during checks. Private key bytes are never entered here.

Verify the machine's host key

A scan finds a key but cannot prove the machine's identity. Compare its SHA256 fingerprint through the machine console or another trusted channel.

On Linux, read the server key with ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub. On Windows, use its matching public host-key file under C:\ProgramData\ssh. Never paste the private host key.

Saved machine actions

Checks run from the ECPA host using its current Windows account. A connection check runs only fixed OS/user diagnostics.



Private profile transfer
Exports contain hostnames, usernames, public host keys and local key paths. They contain no private key bytes or passwords, but are still private machine inventory: never publish them to GitHub.
On a replacement Windows host, install OpenSSH Client and re-provision its keys/agent. Update local paths and verify host fingerprints again before connecting.
